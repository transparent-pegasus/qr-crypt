# Qrypt 脅威モデル

## 1. 保護対象資産

| 資産 | 保存場所 | 機密度 |
|---|---|---|
| 平文・復号済み本文 | React メモリーのみ(保存禁止) | 最高 |
| AES 共通鍵 | IndexedDB(CryptoKey, extractable — QR 交換仕様上の要件) | 最高 |
| RSA 秘密鍵 | IndexedDB(CryptoKey, **non-extractable**) | 最高 |
| 共通鍵 QR / 秘密鍵バックアップ QR(将来) | IndexedDB `qrArtifacts` / 画像出力 | 最高 |
| 暗号文 QR | 同上 | 機密(鍵無しでは復号不能) |
| 公開鍵 QR | 同上 | 公開 |
| 設定(方式・EC レベル等) | IndexedDB / テーマのみ localStorage | 低 |

## 2. 保証範囲(spec §2)

本アプリが保証するのは「**アプリケーションが意図的に平文・秘密鍵・共通鍵を外部送信しないこと**」まで。実装上の担保:

- アプリ機能としての API 通信ゼロ(fetch 系クライアント不使用)。許可される通信は新規導入時の PWA 本体・静的アセット取得のみ
- CSP `connect-src 'self'` ほか(`public/_headers`)により実行時の外部送信をブラウザーレベルでも遮断
- 解析・ログ・エラーレポート SDK・外部フォント・CDN 不使用
- 本番ビルドで平文・鍵・QR 内容を console に出さない
- 平文の永続化禁止(localStorage/IndexedDB とも)。バックグラウンド放置時の自動消去タイマー

## 3. 防御対象外(明示的非目標 — アプリ内「セキュリティについて」に全文掲載)

1. OS・ブラウザー・ファームウェアの侵害
2. キーロガー、画面録画、スクリーンショット
3. カメラフレームを取得するマルウェア
4. PWA 初回取得時または再インストール時の供給網侵害
5. 端末の物理的な窃取
6. ユーザー自身による秘密 QR の誤共有
7. ブラウザーデータ削除による鍵の消失

「オフライン表示」はネットワーク状態の補助情報であり、安全性の証明として扱わない・表示しない。

## 4. 攻撃者モデルと対策

| # | 脅威 | 経路 | 対策 | 残余リスク |
|---|---|---|---|---|
| T1 | 暗号文 QR の傍受 | QR 撮影・中継 | AES-256-GCM / RSA-OAEP-3072 ハイブリッド。鍵無しで復号不能 | 鍵漏洩時は復号される |
| T2 | 暗号文の改竄・すり替え | QR 差し替え | GCM 認証タグ+AAD(v/type/alg/keyId/createdAt を結合)検証。失敗時は一切表示しない | 正規の別暗号文への差し替えは検出不能(署名なし。v1 非目標) |
| T3 | 共通鍵 QR の露出 | 撮影・画面共有・クラウド同期・クリップボード同期 | 表示前警告、強確認(チェック必須)、最高機密バッジ常時表示、コピー時の同期注意トースト、ファイル名に鍵情報を含めない | 表示した瞬間の光学的複製は防げない(非目標 6) |
| T4 | RSA 秘密鍵の抽出 | XSS・拡張機能・共有端末 | non-extractable CryptoKey(`exportKey`/`wrapKey` 不能)、CSP で script-src 'self'、外部スクリプトゼロ | OS/ブラウザー侵害(非目標 1) |
| T5 | 悪意ある QR の読取 | 偽装 QR | プレフィックス+CBOR+Zod strict 検証、バイト長固定検証、種別事前選択との整合検査、自動復号禁止(ユーザー操作必須)、読取対象外は明示拒否 | — |
| T6 | 公開鍵のすり替え(MitM) | 偽の公開鍵 QR | 指紋(SHA-256 → 4×4 桁)を取込確認画面に表示し、対面照合を促す文言 | 照合を怠った場合 |
| T7 | 供給網(ビルド・配信) | 依存改竄・Pages 改竄 | aube-lock.yaml コミット、CI は `aube ci`(frozen lockfile)、レジストリ advisory 検査と provenance no-downgrade ポリシー、最小権限 API Token、更新機能なし(オフライン恒久運用) | 初回取得・再インストール時の侵害は非目標 4 |
| T8 | ブラウザー内平文の残留 | タブ放置・端末貸与 | 暗号化後自動消去は既定 ON、バックグラウンド自動消去も既定 ON・固定遅延、「すべての平文を消去」、リロード非復元 | メモリーフォレンジック(非目標 1/5) |
| T9 | IV 再利用による GCM 破壊 | 実装バグ | IV は暗号化毎に CSPRNG 12B。再利用検出テスト・鍵毎新規生成。カウンター方式を採らず状態を持たない | 2^-96 衝突(無視可能水準) |
| T10 | ダウングレード・混同攻撃 | alg/type 書き換え | AAD に algorithm/type/v を封入(書き換えはタグ検証で失敗)、未知バージョン・方式は拒否 | — |
| T11 | ストレージ経由の情報漏洩 | localStorage 誤用 | localStorage はテーマのみ(自動テストで検査)、平文非保存テスト、QR ペイロードは IndexedDB のみ | 端末窃取+プロファイル抽出(非目標 5) |
| T12 | カメラの不正利用 | 常時カメラ | 読取モーダル表示中のみ getUserMedia、閉鎖時トラック停止、Permissions-Policy camera=(self) | カメラマルウェア(非目標 3) |

T8/T11 横断対策として、OnlineGate はオンライン中の全機能を遮断し、offline→online 遷移時に TransientClear を発火して平文・復号結果・結果ペイロードを即時消去する。オフライン表示自体を安全性の証明とは扱わない。

## 5. 設計上のトレードオフ(明示)

- **共通鍵は extractable**: 共通鍵 QR の生成が仕様要件のため。露出面は T3 の UI 対策で縮小。より高い保護が必要な相手には RSA 方式を推奨(秘密鍵は non-extractable)。
- **署名・送信者認証なし(v1)**: 暗号文の真正性(誰が作ったか)は保証しない。エンベロープに署名を導入する場合は v2 とする。
- **createdAt はメタデータ**: リプレイ防止機構はない(オフライン用途では受信者の文脈判断に委ねる)。AAD 封入により改竄のみ検出。
- **秘密鍵バックアップ(OCB1)未実装**: フラグ恒久 OFF。実装時は spec §10.2 の条件(パスフレーズ導出鍵での暗号化・ランダムソルト/IV・復元テスト)を満たすこと。
- **更新経路を設けない**: 更新経路の排除はオーナーの運用ポリシーによる。導入済み端末はオフラインで恒久運用し、新バージョンは完全フォーマット後に新規導入する。

## 6. 検証との対応

- 外部送信ゼロ: e2e でページ内ネットワーク要求のオリジンが self のみであることを確認(§30.5)+ CSP ヘッダー
- 平文非保存 / localStorage 清浄: 統合テスト(§30.3)
- AAD・改竄・誤鍵の復号失敗: 単体テスト(§30.1)
- IV 一意性・長さ: 単体テスト(§30.1)
- 強確認・警告 UI: UI テスト(§30.4)
