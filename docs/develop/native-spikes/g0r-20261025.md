# G0r native relay feasibility — 2026-10-25

This is historical feasibility evidence from a throwaway probe, not a native product release or a security certification. The spike branch is retained separately and must not be merged. Five native hosts exercised app-origin WASM, QR rendering/decoding, relay assembly/playback and gesture-triggered clipboard writes. Real-device camera behavior and independent native PNG payload readback were not established.

Each native host is 14/16. Without activation, WebView2 clipboard writes reached the 8-second observation deadline; the other native hosts rejected them for permission/activation. The headless Chromium baseline also rejected both writes after its automation click (12/16). Those failures are preserved; no permission override was used to turn the historical probe green.

The symmetric fixture is 145 bytes in one frame; the PQ fixture is 1,745 bytes in two frames. The probe used 1,000-byte chunks and 1,024 px EC-Q rendering. These are structural synthetic ciphertext envelopes, not evidence of native encryption/decryption or signature verification. Camera checks reported API/device enumeration only, with `cameraStarted=false`. The successful Web Locks observation is not a relay-bundle requirement; that bundle has no key writer or origin-wide admission lock.

## Clipboard and harness limits

- Windows native inspection reported `ContainsImage=True` and `ContainsText=False` after the image write; Linux offered the `image/png` MIME type; macOS listed image representation types and sizes. These are not exact text or decoded image-content comparisons. Android native clipboard inspection was explicitly skipped. iOS reported `public.png: Promised`; its `pbpaste` observation emitted no bytes. No independent native PNG content readback is claimed for any host.
- Windows used an automated mouse event, Linux an automated click, Android an adb tap. macOS used Tauri eval; iOS used WKWebView native eval. Both eval paths reported active user activation in this measured host. None is a human-tap measurement.
- The retained Tauri probe driver can accept old output if its output directory is reused, and some original drivers accept a report whose gesture was never delivered. The final CI used fresh checkouts and its native records all contain the expected delivered gesture. These harness limitations are why the throwaway driver is not a maintained regression gate. Product tests require a fresh process/profile/output identity and fail on a missing gesture.
- The earlier iOS result at `9cf6f61` did not deliver a gesture; this final result supersedes that specific missing measurement. Automatic clipboard failures remain.

## What this permits

Use the observations to design the native-relay host profile and implement product tests. They do not clear store/package permission gates, minimum-client-OS support, real-device capture/background tests, source-to-binary assurance, independent security review or publication. Each product candidate must be tested using its own source and artifact identity. The device prohibition and residual risks in the [native-relay specification](../../spec/native-relay.md) remain binding.
