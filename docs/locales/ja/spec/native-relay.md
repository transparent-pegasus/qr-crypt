# ネイティブ中継版のホスト契約

[English](../../../spec/native-relay.md)

この契約は、暗号文だけを扱う中継専用バンドル `dist-relay/` のネイティブホストを定めます。実装の仕様であり、ネイティブ版の公開承認や、以下の全プラットフォームへの対応宣言ではありません。最初の製品対象は Windows です。[G0r](../../../develop/native-spikes/g0r-20261025.md) には以前の実現性検証を別に記録しています。[通信仕様](../../../spec/qr-protocol-v2.md)、[脅威モデル](../../../security/threat-model.md)、[セキュリティレビュー](../../../security/security-review.md) も適用します。

## 1. 端末とエディションの境界

**鍵や平文を持つ端末には中継版を入れないでください。Route A の PWA を入れたブラウザプロファイルがある端末も含みます。** アプリ識別子を分けることで偶発的な共有は防げますが、同じ OS ユーザーの full-trust プロセスから、そのプロファイルを保護することはできません。この禁止は撮影・コピー・貼り付けより前に適用し、両言語のアプリ画面、利用者向け文書、各ストアの説明で見える状態にします。

鍵の生成・保存と平文の暗号化・復号はオフライン版だけが行います。ネイティブ中継版が受け付けるのは、正規形式の `sym-message` と `pq-message` の完全な暗号文フレーム集合だけです。他の外枠の種類は拒否します。封筒の検査は構造の検査であり、送信者の認証、暗号化された平文の検査、侵害済みのオフライン端末が暗号文に隠す情報の流出防止にはなりません。独立した本人確認が引き続き必要です。

中継バンドルには、鍵リポジトリ、IndexedDB のアプリ DB、boot-controller、wipe、暗号処理 Worker、Service Worker、到達確認プローブを含めません。ビルド時のモジュールと最終出力の許可リストで構成を検査します。同じバンドルに鍵を書き込む処理がないため、ローカル中継セッションは Web Locks による利用資格の確認をしません。これは端末が安全であることを実行時に証明する検査ではありません。完全版 Web アプリのオリジンに `dist-relay/` を配置してはいけません。そのアプリの中継利用資格の確認を迂回するためです。

オフライン端末は恒久的にオフラインで使い、そのまま更新しません。ストアの自動更新を許容するのは中継版だけで、残留リスクとして扱います。更新、ホスト、ランタイム、OS が侵害されると、正規アプリの動作範囲を超えてカメラ、クリップボード、他の利用者データにアクセスされる可能性があります。中継版の更新は、導入を許可したすべての固定版 Route A PWA、将来はネイティブオフライン版とも相互運用できなければなりません。相手の正確なリリースハッシュと、ストアごとの公開版を台帳に記録します。非互換の通信形式への変更は、オフライン端末のサニタイズと新規導入を含めて別途配布方針を決めます。旧パーサーは併存させません。

## 2. オリジンと同梱資源

| ホスト | 必須のアプリオリジン | 根拠・状態 |
| --- | --- | --- |
| Tauri / Windows WebView2 | `http://tauri.localhost` | G0r で secure context を観測。製品候補ごとに再確認 |
| Tauri / macOS・Linux | `tauri://localhost` | G0r のみ。製品実装と対応下限は未確定 |
| Capacitor / Android | `https://localhost` | G0r のみ。製品実装と対応下限は未確定 |
| Capacitor / iOS | `capacitor://localhost` | G0r のみ。製品実装と対応下限は未確定 |

対象プラットフォームの正確なオリジンを使い、ユーザー情報、別のスキーム、紛らわしいホスト名、既定以外のポートを許可しません。同梱資源だけを正しい MIME 型で提供します。secure context と同梱 WASM の読み込みは実際のホストで測定します。通常の Playwright ブラウザでの成功は代わりになりません。

実行コード、スタイル、読み取り器の WASM はすべてレビューしたバンドルから読み込みます。読み取り器には常に同梱 WASM の場所を指定し、CDN へのフォールバックを持ちません。依存パッケージに残る未使用の CDN テンプレート文字列は、`scripts/relay-bundle-allowlist.mjs` の正確な正規化エントリーだけで許可します。これは測定した文字列の出力を認めるもので、通信や外部オリジンを許可するものではありません。グラフ検査、最終ファイル検査、CSP、実際のリクエスト観測はそれぞれ別の対策です。

サーバーの内容、ライブの manifest、到達確認センチネル、テレメトリー、アップデーター、Service Worker を読み込みません。アプリの外向きリクエストに中継データを載せません。実際のネイティブページを再読み込みしてリクエストを検査し、想定した同梱資源だけで、クエリー文字列や本文がないことを確認します。OS やランタイムの保守通信は、このアプリの主張の範囲外です。

## 3. CSP と引き継げない Web 応答ポリシー

中継ビルドは `metaCspFromHeaders()` を使い、`public/_headers` から meta CSP を生成します。Tauri で置き換えず、`app.security.csp` を null にします。`script-src 'self' 'wasm-unsafe-eval'`、`connect-src 'self'`、`object-src 'none'`、`base-uri 'none'`、`form-action 'none'` と、元のポリシーの他の対応ディレクティブを維持します。script の `unsafe-inline` や汎用の `unsafe-eval` を加えません。引き継いだ `worker-src` は Worker の同梱許可ではなく、中継のグラフ・出力の禁止がさらに狭い制約になります。

WASM/CSP に対応しないランタイムでは、既存の読み取り器の失敗状態を画面に表示します。CDN への再試行や CSP の緩和はしません。テキストから QR への再表示はカメラの準備状態に依存しません。バンドルは `<meta name="referrer" content="no-referrer">` も持ちます。

ネイティブホストは Web 配備の `_headers` を引き継ぎません。UI とナビゲーションの制限は露出を減らしますが、失われたブラウザポリシーを再現するものではありません。

| Web 応答ポリシー | ネイティブ側の契約と残る制約 |
| --- | --- |
| Permissions-Policy | カメラは明示操作後に要求し、マイク、位置情報、USB などを要求しません。許可ダイアログやネイティブ権限宣言は Web のポリシーを再現しません。実際のパッケージ権限を検査します。 |
| COOP / CORP | アプリの最上位ウィンドウを 1 つにし、ポップアップと外部遷移を拒否します。cross-origin isolation や CORP と同等の境界を成立させるものではありません。 |
| X-Frame-Options / CSP frame-ancestors | レビューしたホストが最上位ビューを作り、外部ページを埋め込みません。meta CSP で frame-ancestors は強制できません。 |
| X-Content-Type-Options | 同梱資源にも正しい MIME 型と実行時の確認が必要です。ローカルファイルや単一ウィンドウだけで nosniff を推定しません。 |
| Referrer-Policy | 明示した meta ポリシーが文書に適用されることを、製品の WebView で確認します。 |
| Cache-Control | バンドルは同梱しますが、WebView はプロファイル、キャッシュ、診断情報を残す可能性があります。アプリが保存しないことは、OS やランタイムに痕跡がないという約束ではありません。 |

## 4. ホストの権限とナビゲーション

デスクトップホストは `main` ウィンドウを 1 つ作り、アプリの IPC 権限を付与しません。そのウィンドウを選ぶ inline capability を 1 つ明示し、permissions を空にします。固定した Tauri 実装では、capabilities の指定なし、または空の選択は、既定で capability ファイルを取り込みます。それだけでは拒否ポリシーになりません。生成された実効 ACL と、実際の WebView での呼び出し拒否を検査します。グローバル Tauri API を無効にし、アプリのコマンド、プラグイン、アップデーター、ファイル、ネットワーク、opener、クリップボードのブリッジを登録しません。Tauri 内部の IPC 基盤自体は残ります。

遷移は対象プラットフォームの正確なアプリオリジンだけに許可し、新規ウィンドウとダウンロードのイベントをすべて拒否します。中継 UI に外部リンク、ファイル出力、共有シートを設けません。ソースのポリシーテストではユーザー情報、ホスト名、スキーム、ポートの混同を検査し、ネイティブテストでは遷移、ポップアップ、ダウンロードの実際の拒否を確認します。

これらは正規の WebView とホスト間のインターフェースを制限する対策です。Rust の OS 権限を除去したり、侵害されたランタイムを隔離したり、OS による通信遮断を証明したりはしません。開発用 EXE は AppContainer パッケージではありません。Windows のパッケージ工程では AppContainer を先に試し、実際の権限と動作を検査します。失敗しても無断で `runFullTrust` に切り替えません。必要なら残留リスクの判断を記録します。Android では将来、マージ後 manifest から INTERNET が除かれることを確認します。iOS には同等の汎用外向き通信権限を外す仕組みがありません。これらのパッケージ方針は G0r で成立を確認したものではありません。

製品成果物にはテスト用 WebDriver プラグイン、レポート受信処理、追加サーバー、テストコマンドを含めません。テスト用 WebView2 CDP 設定は、起動するプロセスの環境だけから渡せます。配布前には実際のパッケージを検査し、意図的にテスト機能を混入させた拒否確認用フィクスチャーも実行します。ソースとロックファイルの確認だけでは足りません。

## 5. カメラ、終了処理、クリップボード

カメラは明示操作と同梱読み取り器の準備成功を必要とします。既存の準備期限と失敗のラッチを `getUserMedia` より前に適用します。閉じる操作、pagehide、非表示化ではすべてのカメラトラックを止め、中継セッションを破棄します。未完了のカメラ取得や再表示の準備も取り消し、遅れて完了してもセッションを再開しません。復帰後も閉じた空の状態にします。

Windows ホストは実際の最小化・非表示・復帰を WebView の可視性へ反映しなければなりません。固定した Tauri/Wry の挙動を確認し、反映されない状態があれば、ネイティブコントローラーの可視性を設定するか、反映に失敗したときにウィンドウを閉じます。人工的な visibility イベントはフロントエンドのロジック検証にすぎません。ネイティブのゲートでは、自分が起動したウィンドウに対する OS 操作で、動作中と準備中の両方を確認します。実機カメラの挙動は公開候補で別途測定します。

クリップボードへ書き込むのは明示的なコピー操作だけです。製品はクリップボードを読み取らず、貼り付けには利用者の通常の入力操作を使います。セッションを閉じても、OS、履歴、同期サービスにクリップボードの内容が残る可能性があります。セッション終了でそれらのコピーが消えるとは主張しません。

Windows 製品のゲートでは、コピーごとにクリップボードを既知の初期状態にして、trusted click の後、テストコードからネイティブクリップボードを読みます。テキストの完全一致と、取得したビットマップ・PNG が期待する QR フレームに復号されることを確認します。書き込み Promise の成功や、画像があるというフラグだけでは足りません。テストを通すために製品へ読み取り権限やプラグインを加えません。読み戻せなければゲートは未完了です。

## 6. 保存と画面上の識別情報

アプリが永続保存するのは言語設定 `oc-lang` だけです。テーマはシステムに従い、設定を書き込みません。暗号文、フレーム、鍵、平文を IndexedDB、CacheStorage、Cookie、localStorage、ファイルへ保存しません。通常のメモリー解放はフォレンジック上の消去ではありません。スクリーンショット、スワップ、クラッシュレポート、キーボード・IME、クリップボード履歴、WebView やランタイム内のコピーはこの保証の範囲外です。

中継エディション名、ルート package の版、完全な `VITE_BUILD_SHA` を画面に表示します。その SHA をビルドした候補とテスト証拠に対応させます。エディション別の識別子はセキュリティ境界ではなく、画面のハッシュだけで実行ファイルを認証することもできません。

端末の禁止事項、カメラに周囲も映ること、独立監査が未実施であることを、すべての中継操作より前に表示します。英語と日本語の内容を揃えます。国家レベルの攻撃にも安全、独立監査済み、release-approved とは表現しません。プロジェクトの公開区分は experimental のままです。ストア向け文面には監査未了の事実を正確に伝え、未完成のテスト製品を完成した公開版として扱いません。

## 7. 最初の Windows 実装対象

2026-11-03 確認。最初の対象は x64 の Windows 11 ビルド 26100 以降で、**Microsoft が保守中のリリースとエディションに、最新のセキュリティ更新を適用していること**が条件です。この日付では Home/Pro は 25H2 以降、Enterprise/Education は保守期間内の 24H2 を利用できます。WebView2 は保守中の Evergreen とし、機能上の基準をメジャー 155 以降とします。これは選定した実装対象の下限で、最小クライアント環境での互換性測定を終えた意味ではありません。G0r の UA は Edg/155 を報告しましたが、Windows 11 クライアントや対象リリース全体を測定していません。

[Windows のリリース情報表](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information) の保守日付は次のとおりです。

| エディション・リリース | 確認時の保守状態・日付 |
| --- | --- |
| Home/Pro 24H2 | 更新終了。対象外 |
| Home/Pro 25H2 | 2027-10-12 |
| Enterprise/Education 24H2 | 2027-10-12 |

表の ISO 日付を原文どおり保持しています。別の [Home/Pro](https://learn.microsoft.com/en-us/lifecycle/products/windows-11-home-and-pro) と [Enterprise/Education](https://learn.microsoft.com/en-us/lifecycle/products/windows-11-enterprise-and-education) のライフサイクルページは Pacific Time と明記し、日時の表示が異なる場合があります。その表示日時をこの表の日付と無断で置き換えません。保守状態は導入時だけでなく、候補の検証時にも再確認します。[WebView2 の配布資料](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution) が説明する Evergreen の保守も必要で、数値上の下限を満たす古いメジャー版だけでは足りません。

Windows Server 2025 CI はランナーでの測定であり、Windows 11 クライアントとの互換性確認ではありません。Android、iOS、macOS、Linux の製品下限は、それぞれのネイティブ実装と保守中ランタイムの確認まで未確定です。G0r のエミュレーター・シミュレーターの版を対応下限にはしません。未検証の下限を広げるために CSP を緩めません。

## 8. 証拠と公開ゲート

| ゲート | 必要な証拠 |
| --- | --- |
| 中継バンドル | 固定依存のグラフと最終ファイル、正確な許可リストの拒否例、Chromium・WebKit 共通動作、API ごとの測定制約 |
| Windows ホスト | 実際の release EXE のハッシュ、ソースとロックの識別、生成 ACL、正確なオリジンの制限、ネイティブクリップボードの内容、OS の終了処理、ランタイムと OS の版、人工カメラの制約 |
| パッケージ・配布 | 実際の権限とプラグイン、意図しない待ち受けがないこと、混入フィクスチャーの拒否、固定版との相互運用台帳、ストア識別情報、正確なプライバシー・掲載文面 |
| 本番公開 | 同じ候補を公開直前に実機で測定した結果、独立レビュー、残る公開阻害要因すべての明示的な扱い |

オーナーの決定を維持します。実装順は Windows Store → Android → iOS → PC 直接配布とし、各ストアは自分のゲートを満たせば独立して申請できます。初期支出を追加せず、個人アカウントを使い、iOS CI は macOS ランナーを使います。実機測定は各本番公開候補とネイティブオフライン版のゲート直前まで遅らせますが、免除しません。オーナーか担当の協力者が必要な端末を測れなければ、そのプラットフォームの公開を延期します。未決の native-offline の wipe、パッケージ方式、ランタイムの保証方式は、この契約では決めません。

境界を正確に分類します。グラフ検査、入力検査、セッション終了はアプリの対策です。端末の分離と撮影環境の管理は配備上の要件です。更新されるホスト、ランタイム、ストアの供給網は構造上の残留リスクです。実機測定、パッケージ検査、独立レビューは外部の保証です。いずれも国家レベルの攻撃者に対する認証ではありません。
