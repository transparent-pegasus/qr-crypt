QR CRYPT

The premise

Any device that has ever connected to a network may already be compromised.

So you encrypt and decrypt on a device that stays fully offline. The only thing that goes onto the network is scrambled text nobody else can read.

Keep reading

Where the network stops

Nothing crosses this line but light — a QR code on one screen, a camera on the other.

What this is

Encrypt offline, carry it by QR code

QR Crypt is a small app that runs on a device you keep permanently offline. You type a message; the app encrypts it and shows the result on screen as a QR code. Your everyday phone scans that code, converts it to a text string, and sends it through any ordinary messenger. The person receiving it does the same in reverse. Only the two offline devices ever see the real message. The online device in between carries nothing but scrambled text.

  • No accounts. No servers. No request ever carries your message or your keys.
  • Two devices per person. One offline, one online.
  • Open source, Apache-2.0, and not independently audited.

Encryption

Convenience, or long‑term strength

Pick the one that matches how long the message has to stay private.

AES-256

For everyday messages

The encryption standard in use almost everywhere today. As of 2026 there is no known practical way to break it. QR Crypt uses it by default: one QR code, and a key you hand over in person.

ML-KEM-1024

For messages that must stay private for decades

A big enough quantum computer will eventually break the way keys are shared today. ML-KEM-1024 is built to resist that, so even against a state-level attacker a message is expected to stay unreadable for decades. It is heavier: the message becomes a sequence of QR codes.

Getting it

Two ways to install it

Route A

Verify the signed ZIP

This is the default route. On a computer you trust, download the signed release and verify its signature and checksum there, using values you obtained some other way. Move it to the offline device, unzip it, and serve the folder from a static web server bound to 127.0.0.1 alone. As the bundled INSTALL.txt requires, use a server obtained through an independent trusted process, and apply the headers and redirects shipped with it. Opening index.html straight from a file path does not work: storage isolation does not hold there, and another local HTML file can end up able to read your keys. Whatever you carry it on, a USB stick or an SD card, has to be trusted too: anything that can alter the storage can alter the app.

Get the latest release github.com/transparent-pegasus/qr-crypt

Route B

Install it from the live origin

On the device you will keep offline, open this site and choose Install or Add to Home Screen, then disconnect it from every network. This route has no integrity check you can perform: control of the origin, TLS, or CDN lets an attacker send an altered bundle to just one device without detection, and the Service Worker persists it. The device also keeps that live origin. If it reconnects, a reachability probe goes to the same origin; wipe waits for the sentinel response, so that beacon necessarily leaves before wipe. Route A points only at 127.0.0.1; after its dedicated server is stopped and its reserved port is not reused, there is nobody listening. Never rely on airplane mode to make a device trustworthy.

Open the app qr-crypt.pages.dev

Using it

How a message travels

Through all six steps the readable message never leaves the offline device. What crosses the seam is ciphertext plus the framing information needed to carry it. The key exchange is what differs by method: a symmetric key needs to be read in one direction only, while a post-quantum identity needs each side to read the other's public key whenever the message is signed or the conversation runs both ways. What follows is the post-quantum identity route.

Online assume it is breached

Offline only you can read it

  1. Each person creates their own key

    >Create tab

  2. Each person loads the other's key

    >Import tab

    Do this face to face and compare the fingerprints on screen. Nothing in the app can check that a key belongs to the person you think it does.

  3. The sender encrypts the message

    >Encrypt tab

    Encrypt it with the recipient's key. If you picked a signed suite, your own key marks it as yours.

  4. The online device scans the QR code from the offline screen.

  6. The offline device scans the QR code from the online screen.

    The recipient decrypts and reads it

    The readable message never leaves this device.

Warnings

Read this before you rely on it

Once a device has been online, you can never fully trust it again

Airplane mode is only a setting. Software on a compromised device can make it look offline when it is not. Treat a device as offline only once it is disconnected for good and stays that way.

If the offline device goes online, the app erases all its data

It deletes the keys and data it stores, but deleted is not gone. The deletion is best-effort, and the app tells you when a step of it fails. Traces can often be pulled back off the hardware. If it truly has to be unrecoverable, wipe the storage with a method suited to the medium (NIST SP 800-88) or destroy the device.
