QR CRYPT

The premise

Any device that has ever connected to a network may already be compromised.

So you encrypt and decrypt on a device that stays fully offline. The only thing that goes onto the network is scrambled text nobody else can read.

Keep reading

Where the network stops

Nothing crosses this line but light — a QR code on one screen, a camera on the other.

What this is

Encrypt offline, carry it by QR code

QR Crypt is a small app that runs on a device you keep permanently offline. You type a message; the app encrypts it and shows the result on screen as a QR code. Your everyday phone scans that code, converts it to a text string, and sends it through any ordinary messenger. The person receiving it does the same in reverse. Only the two offline devices ever see the real message. The phones in between carry scrambled text, though anyone watching can still see how big it is and how many pieces it came in.

  • No accounts. No servers. No request ever carries your message or your keys.
  • Two devices per person. One offline, one online.
  • Open source, Apache-2.0, and not independently audited.

Encryption

Convenience, or long-term strength

Pick the one that matches how long the message has to stay private.

AES-256

For everyday messages

The encryption standard in use almost everywhere today. As of 2026 there is no known practical way to break it. QR Crypt uses it by default: one QR code, and a key you hand over in person.

ML-KEM-1024

For messages that must stay private for decades

A big enough quantum computer will eventually break the way keys are shared today. ML-KEM-1024 is built to resist that, so even against a state-level attacker a message is expected to stay unreadable for decades. It is heavier: the message becomes a sequence of QR codes.

Getting it

Two ways to install it

Route A

Install it, then keep this device offline

On the device you will keep offline, open the site in a browser and choose Install or Add to Home Screen. Then disconnect that device from every network and leave it that way. Airplane mode is not enough.

Open the app qr-crypt.pages.dev

Route B

Install from a ZIP file

On a computer you trust, download the signed release and verify its signature and checksum there, using values you obtained some other way. Move it to the offline device, unzip it, and serve the folder from a local web server; opening index.html straight from a file path does not work. Whatever you carry it on, a USB stick or an SD card, has to be trusted too: anything that can alter the storage can alter the app.

Get the latest release github.com/transparent-pegasus/qr-crypt

Using it

How a message travels

Six steps. Colour and placement tell you which device each one happens on. This is the ML-KEM-1024 route.

Online assume it is breached

Offline only you can read it

  1. Each person creates their own key

    >Create tab

  2. Each person loads the other's key

    >Import tab

    Do this face to face and compare the fingerprints on screen. Nothing in the app can check that a key belongs to the person you think it does.

  3. The sender encrypts the message

    >Encrypt tab

    Encrypt it with the recipient's key. If you picked a signed suite, your own key marks it as yours.

  4. The online device scans the QR code from the offline screen.

    Scan the QR code and send the text

    Online mode>

  5. The recipient turns the text back into a QR code

    Online mode>

  6. The offline device scans the QR code from the online screen.

    The recipient decrypts and reads it

    >Decrypt tab

    The readable message never leaves this device.

Warnings

Read this before you rely on it

Once a device has been online, you can never fully trust it again

Airplane mode is only a setting. Software on a compromised device can make it look offline when it is not. Treat a device as offline only once it is disconnected for good and stays that way.

If the offline device goes online, the app erases what it is holding

It deletes the keys and data it stores, but deleted is not gone: traces can often be pulled back off the hardware. If it truly has to be unrecoverable, wipe the storage with a method suited to the medium (NIST SP 800-88) or destroy the device.
